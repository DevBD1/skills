## Continuous Development Workflow

- Use `docs/development-cycle.md` for the complete idea-to-release workflow.
- Use `docs/sprints/` for backlog, sprint planning, work logs, review, and retro.
- Use `CHANGELOG.md` as canonical release history.
- Use `docs/releases/` for versioning, release prep, tag, artifact, and publishing rules.
- Tie non-trivial work to a backlog or sprint item before implementation.
- Use Conventional Commits: `type(scope): summary`.
- Prefer PR-first delivery and release prep PRs for version bumps.
